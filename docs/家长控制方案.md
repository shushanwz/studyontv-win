# 家长控制功能 · 设计方案

> 状态：待开工（方案已定稿，三处决策已确认）
> 版本目标：v0.2.0 —— 从"教孩子攒时长"变成"不答题就动不了电脑"

## 1. 目标与非目标

### 目标

1. 程序启动即全屏锁屏，除答题外无法操作电脑。
2. 答题赚额度，锁屏页可点 10 / 15 / 20 / 25 分钟四档解锁，解锁后自由使用电脑相应时长。
3. 时长到点自动回锁，无提示、无过渡。
4. 家长密码可越过整条链路；进入设置界面（规则/题库）同样需要密码。
5. 跨重启有效：关掉程序、重启电脑、强杀进程，重新打开仍是锁屏。

### 非目标（明确不做，避免过度工程）

- 不做内核驱动级拦截。
- 不接管 Ctrl+Alt+Del（Windows 的 Secure Attention Sequence，用户态程序原理上拦不住）。
- 不监控孩子实际在玩什么、不采集使用记录上传。
- 不在本版本做远程控制（手机端远程解锁留作 v0.3 可选项）。

## 2. 一个必须先讲清的事实

**杀掉进程，锁屏就消失。** 程序不是操作系统，任务管理器里一结束，桌面立刻恢复。窗口做得再硬也没用——所以本方案的封锁强度靠三层叠加，而不是靠"全屏置顶"这一件事：

| 层 | 作用 | 拦住的行为 |
| --- | --- | --- |
| 窗口层 | 无边框全屏 + Topmost + 抢焦点 + 忽略 WM_CLOSE | 点别处、切换窗口、关窗 |
| 输入层 | 低级键盘钩子吞热键 + 鼠标裁剪 | Win、Alt+Tab、Alt+F4、Esc、Ctrl+Shift+Esc、鼠标移出 |
| 进程层 | 双进程心跳互保 + 退出需密码 + 可选禁用任务管理器 | 结束进程、退出程序 |

三层全上之后，剩下唯一的口子是 Ctrl+Alt+Del → 任务管理器 → 结束进程（若禁用了任务管理器，则要重启）。这个口子靠"看门狗 3 秒内重新拉起并回锁"把它压成"杀了也没用，只是白等 3 秒"。

注意：这条系统热键是**客观存在的事实**，不是本程序提供的功能。界面上不写、不引导、不提示——解锁通道只有家长密码一条。这里记下来是为了让后续维护的人知道封锁强度的上限在哪，不至于误以为已经封死。

再往上就是账户级封锁（受限账户 + 替换 Winlogon Shell），那属于另一个重量级，本次不做。

## 3. 状态机

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ┌─────────┐   攒够余额    ┌─────────┐  点档位  ┌──────────┐
   │ LOCKED  │ ───────────▶ │ 可解锁  │ ──────▶ │ UNLOCKED │
   │ 锁屏答题 │              │ 档位亮起 │         │ 自由使用 │
   └─────────┘              └─────────┘         └──────────┘
        ▲                                          │
        │            倒计时归零 / 关程序 / 心跳中断    │
        └──────────────────────────────────────────┘
```

四种进入锁屏的路径，全部归一到 `LOCKED`：

| 触发 | 检测方式 | 处理 |
| --- | --- | --- |
| 倒计时归零 | 主循环每秒比对 `monotonic` 与 deadline | 立即回锁，不弹提示 |
| 解锁期间关程序 | `WM_DELETE_WINDOW` 需密码；合法退出写 `locked` | 正常退出 |
| 强杀 / 崩溃 | 下次启动读到 `state == unlocked` 且 deadline 未到 | 直接回锁，记一条 `abnormal_exit` |
| 重启电脑 | 启动时读 state | 同上 |

关键设计：**不信任"已解锁"状态跨进程存活**。程序不在运行就等于锁着——这样"杀进程 → 立刻重开"拿不到任何便宜。

## 4. 额度模型

复用现有 `Engine` 的 `credit_ms / used_ms / daily_ms`，只加兑换动作，不动原结算逻辑。

- **入账**：答题结算的 `grant` 累加进 `today.credit_ms`（已有逻辑）。星级奖励默认开，1–5 星 = 1/2/3/4/5 分钟，5 题一组通过约 10–15 分钟，刚好卡住第一档。
- **兑换**：`redeem(minutes)` 从 `credit_ms` 扣 `minutes * 60000`，失败返回差额；成功后写 `lock.deadline`。
- **四档按钮**：余额不足的档位置灰，按钮上直接写"还差 5 分钟"，不做无效点击。
- **每日上限**：沿用 `Rules.dailyMinutes`（家长在设置里调，默认 90），由 `used_ms` 累计，到顶当天不再解锁。
- **不跨天结转**：`roll_day()` 清零 credit，与电视版一致。

倒计时基准用 `time.monotonic()`。Windows 下该值包含睡眠时间，合上盖子也算消耗——这是想要的行为。同时每 10 秒把 wall clock 的 deadline 落盘，供重启后判断。

**时钟回拨检测**：每次心跳比较 `now` 与 `last_seen`，若 `now < last_seen - 90s`，判定系统时间被改，立即锁屏并累加 `tamperCount`。

`data/state.json` 新增两节，其余字段不动：

    "recovery": {"hash": "", "used": false},

    "hardening": {
      "keyboardHook": true,

      "disableTaskMgr": false
    },
    "banksRequirePassword": true,

`Rules` 不新增每日上限字段，避免两处数据源打架。`tiers` 放 `parent` 而非 `Rules`——它属于家长策略，不是玩法规则。

## 6. 密码

| 项 | 做法 |
| --- | --- |
| 存储 | PBKDF2-HMAC-SHA256，16 字节 `os.urandom` salt，260000 次迭代，只存 hash/salt/iters/algo |
| 强度 | 最少 6 位，允许纯数字（家长要好记）。**4 位数字仅一万种组合，哈希扛不住暴力破解，真正的防线是下面的错误锁定** |
| 错误锁定 | 连错 5 次 → 冷却 60 秒，之后 120 / 300 / 900 秒递增封顶；计数落盘，重启不清零 |
| 恢复码 | 首次设密码时生成 `XXXX-XXXX` 一次性码，界面强制显示并要求抄写；忘记密码时用它重置 |
| 校验时机 | 提交时算 hash 比对，用 `hmac.compare_digest` 常数时间比较 |

密码的六种用途：临时解锁、进设置页、改密码、退出程序、重置今日额度、关闭家长控制。

## 7. 设置门的粒度

- 「规则设置」「题库管理」点击即弹密码框；验证通过后 **本进程内 5 分钟免重复询问**（`settingsGraceSeconds`），家长来回切页不用反复输。
- 「关于」不设门。
- 「退出程序」：锁屏状态下必须密码。解锁状态下允许直接退出，但退出一律写回 `locked`。

## 10. 关键流程（伪代码）

启动：

```
enable_dpi_awareness()
locker = LockController(storage)
locker.recover_from_crash()      # unlocked 且 deadline 未到 → 回锁 + abnormalExit++
if parent.enabled and locker.is_locked():
    start_watchdog()             # B 级
    install_keyboard_hook()      # A 级
    enter_lock_screen()          # 全屏
else:
    enter_normal_shell()
```

解锁：

```
def redeem(minutes):
    if minutes not in parent.tiers: raise
    need = minutes * 60000
    if today.credit_ms < need: return {"ok": False, "short": need - credit}
    if today.used_ms >= rules.daily_ms(): return {"ok": False, "reason": "quota"}
    today.credit_ms -= need
    lock.deadline = monotonic() + minutes * 60
    lock.state = "unlocked"
    save_state()
    return {"ok": True, "seconds": minutes * 60}
```

回锁：

```
def tick():
    if lock.state != "unlocked": return
    if monotonic() >= lock.deadline:
        force_lock("timeup")
```

看门狗（独立进程）：

```
每 2 秒:
    if 父进程不存在 or 心跳文件 mtime 超过 8 秒:
        重新拉起 run.py --relock
        自己退出
```

主进程每 2 秒检查看门狗 pid，死了重新拉起。

## 11. 解锁通道

只有一个对外通道：**家长密码**。界面上锁屏页底部给一个「家长解锁」入口，点开是密码框，密码正确后可选「解锁 45 分钟 / 解锁到明天 / 直接退出程序」。

密码之外的替补手段，全部不写在界面上，只写在 README 里给家长备查：

| 通道 | 触发 | 适用 |
| --- | --- | --- |
| 恢复码 | 密码框里点「忘记密码」，输入首次设置时抄下的 8 位码 | 忘密码 |
| `unlock.flag` | 在程序目录放一个同名空文件，启动时跳过锁屏并自动删除 | 程序异常、家长急用 |
| 安全模式 | 安全模式不启动本程序（本版不做开机自启） | 彻底救砖 |

**界面文案约束**：锁屏页不出现任何系统热键提示（Alt+Tab、Ctrl+Alt+Del 之类一律不写），避免把绕过方法教给孩子。底部只留「家长解锁」四个字。

## 13. 风险与回滚

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 键盘钩子回调阻塞 | 全系统输入卡顿 | 回调只做判断立即返回，不写盘不弹窗；调试期用超时看门狗自动卸载钩子 |
| `ClipCursor` 未复位 | 鼠标锁死在某区域 | 进程退出 / 崩溃时由系统自动释放；启动先 `ClipCursor(None)` 复位一次 |
| 注册表 `DisableTaskMgr` 残留 | 家长自己开不了任务管理器 | 写 `pending_restore` 标记，下次启动先还原；默认关闭该项 |
| 看门狗与主进程互相拉起进入死循环 | CPU 占满 | 拉起间隔 3 秒 + 30 秒内拉起超过 5 次则放弃并写日志 |
| 家长彻底忘密码 | 锁死 | 恢复码 + `unlock.flag`；系统热键客观上仍可用，但不作为设计通道宣传 |

**动工第一步**：`git init` + 首次提交打 tag `v0.1.0`，再加 `docs/`。后面每个阶段一个 commit，出问题能退回。

## 15. 防呆：没设密码就不许锁屏

这是实现 P1 时补进方案的硬约束，顺序不能反：

```
启动 → 读 state.parent
        ├─ 没有密码 → 进「家长设置向导」，设完密码才允许进入锁屏
        └─ 有密码   → 正常进入锁屏
```

理由很直接：**锁屏的第一道门就是密码，密码没设就锁，等于把家长自己关在外面**。所以「开启家长控制」这个动作实际上等于「设置密码」这一步完成的那一瞬间，不是勾选一个开关。

同理，设置向导里必须同时显示恢复码并要求家长抄写——这一步不能跳过，也不能"稍后再说"。

| Win / Win+X / Win+D | 拦。Win 键按下期间所有键一并吞掉，避免组合漏网 |
| Alt+Tab、Alt+Esc、Alt+F4 | 拦 |
| Ctrl+Esc、Ctrl+Shift+Esc | 拦 |
| 鼠标点任务栏 | 拦。全屏置顶窗口盖住任务栏，且光标被 `ClipCursor` 限制在窗口内 |
| 换前台窗口（其他程序抢焦点） | 拦。每 2 秒抢回一次 |
| 任务管理器结束进程 | **挡不住，但 2–5 秒后被看门狗拉回锁屏** |
| Ctrl+Alt+Del → 任务管理器 | 拦不住（系统保留的安全注意序列，用户态无权限）。这是硬上限 |
| 多显示器 | **锁屏窗口只覆盖主屏**；光标被限制在主屏矩形内，但副屏桌面仍可见可点。本版不做多屏锁定 |
| 关机 / 重启 / 注销 | 未拦截。强行截断属于系统级操作，拦了容易把系统搞坏，不做 |
